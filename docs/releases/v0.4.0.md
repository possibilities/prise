# Prise v0.4.0 — "Center Stage"

A breaking release reshaping the custom tab bar contract: structured layout,
centered-focus windowing, and cell-precise edge clipping.

## Highlights

- **Structured `tab_bar.render` contract** — Returns `{prefix, tabs, suffix}`
  instead of a flat segment list
- **Centered-focus windowing** — Active tab stays centered (tmux-style) when
  space permits; boundary tabs clip cell-precise
- **Gutter glyphs** — `<` / `>` shown at edges when tabs are hidden off-screen
- **`prise.cell_substring` host primitive** — Cell-precise string slicing for
  grapheme-safe truncation

## Breaking Changes

### `tab_bar.render` returns `TabBarLayout`

Custom renderers must now return a table with three slots:

```lua
return {
    prefix = { ... segments ... },
    tabs = {
        { tab_index = 1, segments = { ... } },
        { tab_index = 2, segments = { ... } },
        ...
    },
    suffix = { ... segments ... },
}
```

Core composes the final strip from these slots and applies centered-focus
windowing plus cell-precise clipping to the `tabs` slot only. `prefix` and
`suffix` are never clipped. See **prise**(5) for the full definition.

### `tab_strip_width` callback retired

The `tab_strip_width` config field is gone. Its job — reserving a cell budget
for non-tab content — is now implicit from `prefix` and `suffix` widths. Core
measures those directly and windows the tabs slot into the remaining budget.

### `state.tab_bar_scroll_offset` removed

The persisted scroll offset is gone. Focus-centre is now a pure function of
the active tab index, per-tab widths, and screen width — no state to persist,
no drift to reconcile across resizes.

## Features

### Centered-focus windowing

Tabs slot uses tmux's `format_draw_put_list` algorithm: the active tab stays
visually centered when space permits, shifting only when the window hits an
edge. Boundary tabs that only partially fit are clipped cell-precise via
`prise.cell_substring`, so wide graphemes never split mid-codepoint.

### Gutter glyphs

New `config.tab_bar.gutter_left` and `config.tab_bar.gutter_right` config
fields (string, defaults `"<"` / `">"`) render at the left/right edges when
tabs are hidden off-screen. They appear only when tabs are actually hidden —
never when the full strip fits. Cell-width is measured via `prise.gwidth`, so
multi-cell glyphs work correctly.

### `prise.cell_substring` host primitive

New Zig host primitive: `prise.cell_substring(str, start_cell, end_cell) -> string`.
Walks graphemes via `vaxis.gwidth.gwidth(_, .unicode)`, drops wide graphemes
that would straddle the requested cell boundary, and pads with spaces to the
requested width. Single source of truth for cell-precise truncation — use it
instead of byte-indexed `string.sub` for any content measured in cells.

## Migration

Custom `tab_bar.render` implementations must:

1. Return a `TabBarLayout` table (`{prefix, tabs, suffix}`) instead of a flat
   segment list.
2. Move any fixed-position left-edge content (session headers, mode indicators)
   into the `prefix` slot.
3. Tag each tab entry with its `tab_index` (index into the full unsliced tabs
   input) — core uses this for click-region mapping.
4. Remove any `tab_strip_width` config field; delete the callback function.

The `measure` callback remains required and unchanged: return the integer
cell-width for the given tab. Prefix/suffix widths are measured directly from
their returned segments, not via `measure`.

## Known Limitations

This is alpha software. Expect breaking changes, incomplete features, and
rough edges.
